# Брифинг по проекту (Трек 1) — теория для защиты

**Продукт:** ИИ-секретарь входящих звонков для Ивана Петрова (малый бизнес).  
**Суть:** не чат-бот, а секретарь на линии МТС: поднимает трубку, понимает суть, отвечает голосом/ведёт в чат, пушит Ивану важное, даёт историю и управление сценариями.

---

## 1. Технологии

| Слой | Стек |
|---|---|
| API | Python, FastAPI, Uvicorn, Pydantic, SQLite (SQLAlchemy) |
| LLM | YandexGPT (REST), fallback — локальные/rule-based ответы |
| Речь | SpeechKit STT/TTS; fallback Faster-Whisper + pyttsx3 |
| Живой звонок | WebSocket, VAD (JS), barge-in, WAV 16 kHz |
| UI «приложение МТС» | Flet (web :8550), вкладки Дашборд / История / Звонок / Шаблоны / Настройки |
| Мобильный QR | Лёгкий HTML `/app` на uvicorn :8000 (~8 KB) + cloudflared |
| Уведомления | Telegram-бот (aiogram), привязка только по одноразовому `bind_token` |
| Секреты | `.env` (YC_*, TG_*), не в git |
| Демо жюри | Tunnel + QR, ключи Yandex для полного стека |
| Android APK | `flet build apk` (UI на телефоне → API по публичному URL) |

## 2. Что происходит (сквозной поток)

```
Звонящий → (прод: SIP МТС) / (демо: /call или вкладка «Звонок» / TG)
        → STT (SpeechKit / Whisper)
        → Call Agent (промпт + шаблоны линии + правила маршрутизации)
        → YandexGPT
        → действие: продолжить / в TG / «перевести» (умная заглушка hotline)
        → TTS → голос звонящему
        → CallLog + пуш Ивану в Telegram
        → Иван правит карточку / меняет сценарии в приложении
```

**Disclosure:** один раз за сессию — «вы говорите с ИИ, разговор может записываться».

## 3. Модули и как связаны

```
┌─────────────────┐     HTTP/WS      ┌──────────────────────┐
│ Flet app :8550  │ ←──────────────→ │ FastAPI :8000        │
│ + WebView звонок│                  │ routes_call          │
│ + HTML /app QR  │                  │ routes_live_call     │
└────────┬────────┘                  └──────────┬───────────┘
         │ bind_token                           │
         ▼                                      ▼
┌─────────────────┐                  ┌──────────────────────┐
│ Telegram-бот    │ ←── notify ───── │ call_agent / yandex  │
│ история, пуши   │                  │ speech, scenarios,   │
└─────────────────┘                  │ routing, history DB  │
                                     └──────────────────────┘
```

| Модуль | Роль |
|---|---|
| `call_agent` | Диалоговая логика, intent/action, disclosure, hotline |
| `yandex_llm` + speech providers | Понимание + голос; локальный fallback без ключей |
| `scenarios` / `routing_rules` | Шаблоны и правила **на номер линии** |
| `call_history` / analytics | История, важное, статистика, PATCH карточки |
| `telegram_notify` | Регистрация линии, токен, пуш **только владельцу** |
| `routes_live_call` | Живой WS-диалог (mic ↔ агент) |
| Flet / лёгкий `/app` | Канал МТС: онбординг, настройки, демо |
| TG-бот | Второй канал: пуши + демо-звонок голосом |

**Архитектурный тезис для жюри:** это **Call Intelligence** (Control / Dialog / Events), не монолит АТС. Сейчас транспорт = веб/TG; на проде тот же core + SIP-адаптер МТС.

## 4. Как пройдёт подключение к МТС (CJM Ивана)

### Сейчас (хакатон / UX каналов МТС)

1. Иван открывает «приложение МТС» (Flet, Android APK или QR → `/app`)
2. Вход по номеру линии (заглушка профиля)
3. Согласие на обработку/запись → **Подключить** (≤ 5 мин)
4. Настройка: шаблоны ответов, правила (голос / чат / гибрид)
5. **Перейти в Telegram** → deep link с личным `bind_token` (голый `/start` = отказ)
6. Первый звонок (живой диалог / демо в боте) → пуш + резюме
7. История, важное, правка карточки; при критичном — баннер эскалации

### На проде у оператора (narrative, не код)

| Сейчас | Прод МТС |
|---|---|
| Веб/TG/APK эмуляция трубки | SIP/VoIP-шлюз оператора |
| SQLite + локальный UI | BSS/биллинг, баланс абонента |
| Yandex API (демо) | Контур ЦОД МТС / локальные модели |
| Ручной tunnel/QR | Каталог услуг в приложении МТС |

Подключение = услуга в каталоге МТС → согласие → привязка номера → опционально мессенджер → секретарь на линии без отдельного «ещё одного входа».

## 5. Вопросы жюри — готовые ответы

**Почему не готовый бот / CallGear?**  
Мы не заменяем АТС: встраиваемся в каналы МТС (приложение, баланс, номер), даём секретаря с управлением сценариями и доверием оператора (согласие, disclosure, аудит доступа).

**Где SIP / 99.9%?**  
В прототипе — turn-based/live WebSocket. Контракт Media/Control/Events готов к SIP-адаптеру; SLA и масштаб — требование оператора на пилоте в ЦОД, не на хакатоне. *Не обещать «уже в проде».*

**Данные и зарубежное API?**  
Демо на Yandex Cloud; на проде — локализация в контуре МТС. Согласие абонента при подключении + disclosure звонящему + right-to-review (кто смотрел запись).

**Как не украсть чужой Telegram?**  
Привязка только по одноразовому ключу из приложения; уведомления только на `chat_id` этой линии.

**Точность «понял суть»?**  
STT + LLM + `summary` в истории; Иван правит карточку; шаблоны per-line в промпте; перед защитой — 5–7 живых сценариев.

**Перевод на человека?**  
Умная заглушка: оффтоп/приманка → уточнение, не ложная эскалация; реальный handoff — следующий этап с SIP.

**Почему Flet / APK, а не нативное МТС?**  
Прототип UX «как в экосистеме МТС»; прод — встраивание в существующее приложение/ЛК, не новый бренд. APK на защите = удобный показ на телефоне жюри.

**Что с матом / токсиком?**  
Content filter + сценарии отказа; правила маршрутизации.

**Один номер / масштаб?**  
Пилот — горизонтальное масштабирование core + адаптеры; пики (рабочие часы) — очередь/автоскейл в ЦОД.

## 6. Финансовая часть (для питча)

ТЗ прямо просит: **оплата с баланса МТС**, модели подписка / минута / freemium, **агентская доля с оператором**, не разовая лицензия «в обход» МТС.

### Предлагаемая модель (допущения команды — озвучить как гипотезу)

| Тариф | Для кого | Цена (ориентир) | Что входит |
|---|---|---|---|
| **Старт** | Фриланс / 1 линия | 299–499 ₽/мес + N мин в пакете | Секретарь, история, TG, базовые шаблоны |
| **Бизнес** | Иван, 1–3 линии | 990–1 490 ₽/мес | Больше минут, аналитика, правила, приоритет |
| **Корп** | Команда | от 3 990 ₽/мес / парк номеров | Дашборд, SLA, CRM-webhook, выделенный контур |

**Сверх пакета:** ~2–4 ₽/мин диалога ИИ (или пакеты минут) — покрывает STT/TTS/LLM.

**Unit-экономика (грубо, для слайда):**
- Себестоимость минуты ИИ (облако) ≈ 0,5–1,5 ₽ → на проде в ЦОД ещё оптимизируется
- ARPU целимся 800–1 200 ₽/мес на активную линию
- LTV при churn 5%/мес и сроке ~12–18 мес — кратно CAC (CAC низкий: каналы МТС, каталог, без платного UA)

**Разделение с МТС (агентская модель):**
- МТС: канал, биллинг, доверие, номер, % от выручки услуги (например 30–50%)
- Мы / вендор: Call Intelligence, модели, UX сценариев, поддержка продукта
- МТС выигрывает: новый ARPU на базе, удержание B2B, дифференциация «умный номер»

**Экономия для Ивана (калькулятор боли):**
- 5–10 пропущенных/некорректно принятых лидов в месяц × средний чек
- 30–60 мин/день на разбор «кто звонил» → возврат времени
- Один спасённый клиентский звонок часто > стоимости подписки

**Чего не обещать:** точные цифры как «утверждённый тариф МТС»; говорить: «модель согласуется с биллингом оператора на старте пилота».
